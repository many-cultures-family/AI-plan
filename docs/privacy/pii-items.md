## 2. 마스킹 종류

> 예시는 모두 가짜 값이다. 규칙 코드: `prototypes/masking/masking.py` → 서버로 옮긴 판은 코드 저장소 `backend/app/privacy.py` (`stepping-stone` PR #28, 아래 2-1절의 보완 포함)

| (직접 고름) | `[가림N]` | 서술형에서 사용자가 골라 가림 `[제안]` | - | MVP 포함 여부 미정 |

가리지 않는 것: 빈칸 라벨(`성명: ____`, `주소 (     )`), 날짜(`2026-11-17`), 짧은 숫자(우편번호·쪽 번호), 안내 문구, 개인정보가 아닌 칸 라벨(`신청인`·`신청일`·`접수일`·`작성일`·`배우자`·`자녀`·`국적`·`성별`·`체류자격`·`서명`·`날짜`·`일자`. 라벨 값은 여기서 끝난다), 서명란 표시(`(인)`·`(서명)`·`(서명 또는 인)`·`(날인)`. 라벨 값은 여기서도 끝난다 — `작성자 성명: ____ (인)`은 빈칸으로 남고 `성명: 홍길동 (인)`은 이름만 가린다)

감지 위치(`start`·`end`)는 **가리기 전 원문 기준**이다. 가린 텍스트에 그대로 쓰지 않는다.

### 2-1. OCR 오인식 보완 (2026-11-23, `stepping-stone` PR #28·#30)

EasyOCR로 가짜 신청서를 읽어 보니, 글자를 잘못 읽은 개인정보가 값 모양 규칙에 안 걸려 그대로 남고 `residual`도 `False`로 통과했다 (노션 트러블슈팅 「OCR 오인식 때문에 개인정보가 가려지지 않고 통과함」). 아래를 더했다.

| # | 보완 | 막는 경우 (가짜 예시) |
| --- | --- | --- |
| 1 | 가리기 전에 숫자 덩어리 속 `O`·`o` → `0`, `l`·`I`·`\|` → `1`로 바꾼다. 영문 단어·`F-6` 같은 짧은 값은 바꾸지 않는다 | `Tel O1O-0000-1234` |
| 2 | 전화·이메일·주민등록번호·외국인등록번호 라벨 뒤 값은 모양과 상관없이 통째로 가린다 (위 표) | `연락처: 010 OOOO 1234`, `이메일 test user@example com` |
| 3 | 세 글자 이상 한글 라벨은 한 글자가 틀려도 라벨로 본다. 바로 뒤에 한글이 붙으면 라벨이 아니다(`연락처로`) | `생년원일 1990.0101`, `이데일 …` |
| 4 | 공백만 사이에 둔 같은 종류 토큰은 하나로 합친다 | `[이메일] [이메일]` |
| 5 | `residual` 검사가 남은 `@`, 날짜를 뺀 9자리 이상 숫자도 본다 | 규칙이 못 알아본 이메일·번호 |
| 6 | 서명란 표시(`(인)` 등)에서 라벨 값을 끊는다 (위 "가리지 않는 것") | `작성자 성명: ____ (인)`이 `([이름])`이 되어 서명란이 사라짐 |

1~3은 넘치게 가리는 쪽이다. 서술형(P4) 브라우저 규칙에도 같은 보완을 넣을지는 `l3-masking.md` 담당이 정한다.

## 3. 받지 않는 것

| 항목 | 이유 | 근거 |
| --- | --- | --- |
| 본인인증 정보 (인증번호·비밀번호) | 받지도 저장하지도 않는다. 우리 로그인도 Google 로그인 | R8 |
| 사전 정보·입력값·서술형 답변 원문 | 서버로 보내지 않는다 | 전제 |
| 주민등록번호·외국인등록번호 **입력 칸** | 허용 형식 목록에 넣지 않는다. 문서에 적혀 있으면 가리고, 서술형에 쓰면 감지한다 | R2, R8, `DATA-MODEL.md` `input_format` |
| 사용자의 '원본과 다름' 사유 글 | 표시만 받는다 | US-03 |
