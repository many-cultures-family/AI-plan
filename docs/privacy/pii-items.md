## 2. 마스킹 종류

> 예시는 모두 가짜 값이다. 규칙 코드: `prototypes/masking/masking.py`
> OCR 문서(P1)는 `[종류]`, 서술형(P4)은 되돌릴 수 있게 `[종류N]`으로 번호를 붙인다 (`l3-masking.md` 4절).

| kind | 토큰 | 찾는 방법 | 가짜 예시 | 한계 |
| --- | --- | --- | --- | --- |
| `resident_no` | `[주민등록번호]` | 값 모양: 6자리 - 7자리, 뒷자리 첫 숫자 1~4·9·0 | `900101-1234567` | 구분 기준 [추정] |
| `alien_no` | `[외국인등록번호]` | 값 모양: 6자리 - 7자리, 뒷자리 첫 숫자 5~8 | `900101-5234567` | 구분 기준 [추정] |
| `phone` | `[전화번호]` | 값 모양: 010·02·031~064·070, `+82` | `010-0000-1234` | 해외 번호(베트남 등) 형식은 `[번호]`로만 잡힘 |
| `email` | `[이메일]` | 값 모양: `@`와 도메인 | `test.user@example.com` | - |
| `address` | `[주소]` | 값 모양: …로/길(…번길) + 번호, …동/읍/면/리 + 번호(번지). 번호 뒤에 `번·개·명` 같은 단위가 오면 제외 / 라벨 `주소`·`Address` 뒤 값 | `서울특별시 가나구 다라로 12` | 번호 없는 주소는 라벨이나 사전 정보 대조가 있어야 잡힘 |
| `name` | `[이름]` | 라벨 `성명`·`이름`·`Name` 뒤 값 (띄어 쓴 괄호 안 값 포함) / 서술형은 사전 정보 이름 대조 | `성명: 홍길동`, `성명 (홍길동)` | OCR 문서의 **라벨 없는 문장 속 이름은 못 찾음** |
| `birth_date` | `[생년월일]` | 라벨 `생년월일`·`Date of Birth` 뒤 날짜 하나 (날짜 모양이 없으면 라벨 뒤 값 전체) / 서술형은 사전 정보 대조 | `생년월일 1990.01.01` | 라벨 없는 날짜는 일부러 남김 (신청일·기한) |
| `long_number` | `[번호]` | 위에 안 걸린 10자 이상 숫자 | `110-123-456789` | 접수번호처럼 개인정보 아닌 번호도 가림 (넘치게 가리기) |
| (직접 고름) | `[가림N]` | 서술형에서 사용자가 골라 가림 `[제안]` | - | MVP 포함 여부 미정 |

가리지 않는 것: 빈칸 라벨(`성명: ____`, `주소 (     )`), 날짜(`2026-11-17`), 짧은 숫자(우편번호·쪽 번호), 안내 문구, 개인정보가 아닌 칸 라벨(`신청일`·`배우자`·`국적` 등. 라벨 값은 여기서 끝난다)

감지 위치(`start`·`end`)는 **가리기 전 원문 기준**이다. 가린 텍스트에 그대로 쓰지 않는다.

## 3. 받지 않는 것

| 항목 | 이유 | 근거 |
| --- | --- | --- |
| 본인인증 정보 (인증번호·비밀번호) | 받지도 저장하지도 않는다. 우리 로그인도 Google 로그인 | R8 |
| 사전 정보·입력값·서술형 답변 원문 | 서버로 보내지 않는다 | 전제 |
| 주민등록번호·외국인등록번호 **입력 칸** | 허용 형식 목록에 넣지 않는다. 문서에 적혀 있으면 가리고, 서술형에 쓰면 감지한다 | R2, R8, `DATA-MODEL.md` `input_format` |
| 사용자의 '원본과 다름' 사유 글 | 표시만 받는다 | US-03 |

## 4. `DATA-MODEL.md`·API 문서와 다른 점 (PM·담당자 확인 필요)

`DATA-MODEL.md`는 PM만, API 문서는 각 담당자만 고치는 문서라 여기서 고치지 않는다. 전제가 확정되면 아래를 반영해야 한다.

| # | 지금 문서 | 전제에 맞추면 | 영향 |
| --- | --- | --- | --- |
| 1 | `DATA-MODEL.md` `prior_info` 모델 (서버 암호화 저장) | 서버 모델에서 뺀다 | US-04 인수 조건 "그 사용자의 사전 정보로 저장" (팀이 직접 고침) |
| 2 | `DATA-MODEL.md` `field_answer` 모델 | 서버 모델에서 뺀다 | `mismatch_acknowledged`(R3 예외 결정)도 브라우저로 |
| 3 | `DATA-MODEL.md` `privacy_detection`, `review_suggestion` 모델 | 서버 모델에서 뺀다 (원문 위치·답변 일부를 담기 때문) | T4 삭제는 브라우저에서 |
| 4 | `VIRTUAL-FORM-API.md` 입력값 저장·불일치 계산 API | 불일치 계산은 브라우저에서. 저장 API는 필요 없음 | 화면 담당 |
| 5 | `DATA-MODEL.md` 성공 판정(R9)을 규칙 엔진이 확인 | 서버에 값이 없어 확인할 수 없다 | `data-flow.md` 5절 #2 |
| 6 | `privacy_detection.kind`: `phone`, `email`, `resident_no`, `alien_no`, `address` | `name`, `birth_date`, `long_number`를 더할지 결정 | 사전 정보 대조로 이름·생년월일을 찾을 수 있게 됨 |
| 7 | 마스킹 토큰 형식 없음 | 2절 표 + `l3-masking.md` 4절 | L1·L3 프롬프트 |
