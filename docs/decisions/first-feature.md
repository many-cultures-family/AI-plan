# 우리 팀의 첫 기능

- 작성일: 261102
- 고른 스토리: `US-01` (기능 ID `F-01`)

- 고른 이유 (우리 팀 상황에서): 저희 서비스 특성 상 기능에 순서가 있어 특정한 기능을 하나 선택하는 것보다 처음부터 하기로 했습니다.
- 고르지 않은 후보와 이유 (다음 시간 이후에 다시 볼 것)
    - US-02, US-03: L1 호출의 키·실패 동작·저장 응답을 먼저 정해야 함
    - US-05: L3 호출과 모호한 인수 조건
    - US-06, US-07: 선택 스토리. US-07을 필수로 올릴지 정한 뒤 다시 봄

## 2. 완성 기준 (인수 조건에서 가져옴)

| # | 인수 조건 (`backlog.md` 원문) | 오늘 만드나 | 테스트할 내용 (입력 → 기대 결과, 인수 조건·`API.md`에 적힌 것만) / 확인 방법 |
| --- | --- | --- | --- |
| 1 | PDF·이미지 파일을 올리면 작성 건이 '업로드됨'으로 생긴다. | 예 | 테스트할 내용(인수 조건 1): PDF·이미지 파일을 올리면 작성 건이 '업로드됨'으로 생기는지 (정상) / 파일이 없거나 PDF·이미지가 아니면 작성 건을 만들지 않는지 (실패, `API.md` 항목 1 실패 응답)<br>입력: 가짜 또는 빈 샘플 PDF 1개, 가짜 또는 빈 샘플 PNG 또는 JPEG 1개 (이름·연락처·등록번호 등 개인정보 없음, 실제 문서 사용 금지) / 파일 없이 요청 / PDF·이미지가 아닌 파일 1개<br>기대 결과(인수 조건 원문에 적힌 것만, 없으면 미정): 작성 건이 '업로드됨'으로 생긴다. `API.md` 기준 `POST /api/drafts`, 성공 시 `201`, 응답에 `draft`(`id`, `status`=`수정`, `step`=`upload`)와 `document`(`mime_type`, `page_count`), '업로드됨'은 `status`=`수정` + `step`=`upload`에 대응 (API.md 합의 후 확정). 파일이 없으면 `400 FILE_REQUIRED`, 허용 밖 형식이면 `415 FILE_TYPE_NOT_ALLOWED`이고 작성 건을 만들지 않음, 오류 형식은 `{"detail": {"code": ...}}` (API.md 합의 후 확정). 이미지(PNG, JPG)의 `page_count`는 1 (DATA-MODEL.md document.page_count의 '이미지는 1'을 근거로 함, API.md 반영 후 확정). 3쪽 PDF를 올리면 `document.page_count`=3 (근거: DATA-MODEL.md '올린 파일의 페이지 수'). 앞부분만 PDF이고 읽을 수 없는 파일은 `415 FILE_TYPE_NOT_ALLOWED` (API.md에 없는 경우라 API.md 합의 후 확정, 지금은 미정). 10MB·10페이지 초과, 확장자나 Content-Type만 속인 파일은 미정<br>확인 방법(실행한 명령 또는 화면에서 보이는 것): 서버: 실행한 pytest 명령 미실행 / 결과 미실행 / 테스트 파일 위치 미정 (`CODE-STYLE.md` 3번 `backend/tests/`와 실제 루트 `tests/`가 다름). 화면(목 모드를 끈 상태): 연 주소 미실행 / 누른 것 미실행 / 본 문구 미실행 |
| 2 | (정상) OCR이 칸을 읽고 문서 속 개인정보를 모두 가리면 '인식완료'로 바뀐다. | 아니오 | 오늘 안 만듦, 미실행<br>테스트할 내용(인수 조건 2): OCR 인식과 개인정보 가림 뒤 '인식완료'로 바뀌는지 (정상)<br>입력: 미정 (가짜 개인정보가 든 샘플 문서의 형태 미정)<br>기대 결과(인수 조건 원문에 적힌 것만, 없으면 미정): OCR이 칸을 읽고 문서 속 개인정보를 모두 가리면 '인식완료'로 바뀐다. "칸을 읽는다", "모두 가린다"의 판정 기준은 미정 (`API.md` "아직 없는 항목")<br>확인 방법(실행한 명령 또는 화면에서 보이는 것): 미실행 |
| 3 | (실패·거절) 인식에 실패하거나 개인정보가 하나라도 남으면 '업로드됨'에 머물고 다시 올리도록 안내한다. | 아니오 | 오늘 안 만듦, 미실행<br>테스트할 내용(인수 조건 3): 인식 실패나 개인정보가 남은 경우 (실패·거절)<br>입력: 미정 (인식 실패나 개인정보가 남는 경우를 만드는 방법 미정)<br>기대 결과(인수 조건 원문에 적힌 것만, 없으면 미정): 인식에 실패하거나 개인정보가 하나라도 남으면 '업로드됨'에 머물고 다시 올리도록 안내한다. 안내 문구, 응답 형태, 오류 코드는 미정 (`API.md` "아직 없는 항목")<br>확인 방법(실행한 명령 또는 화면에서 보이는 것): 미실행 |
| 4 | (권한) 작성 건은 올린 본인만 볼 수 있고, 로그인하지 않은 사용자는 올릴 수 없다. | 아니오 | 오늘 안 만듦, 미실행<br>테스트할 내용(인수 조건 4): 본인 외 조회와 비로그인 업로드 (권한)<br>입력: 미정 (`API.md` 인증·권한은 "오늘은 없음", 다음에 Google 로그인으로 정함)<br>기대 결과(인수 조건 원문에 적힌 것만, 없으면 미정): 작성 건은 올린 본인만 볼 수 있고, 로그인하지 않은 사용자는 올릴 수 없다. 거절 응답 형태는 미정<br>확인 방법(실행한 명령 또는 화면에서 보이는 것): 미실행 |
