# 로그인 API 약속 (화면과 서버가 주고받는 것)

> **저장 위치:** `docs/api/LOGIN-API.md`

> **사용 방법**
> 1. 로그인 기능(Google 로그인)의 항목만 씁니다. 업로드 등 다른 기능은 `API.md`에 씁니다. 개발자1과 개발자2가 **구현하기 전에 같이 읽고 약속**하는 문서이기도 합니다.
> 2. 항목의 **입력·출력·실패 응답**은 `backlog.md`의 **인수 조건**(권한)과 `first-feature.md` 2절 #4에서 가져옵니다. 인수 조건에 없는 응답을 새로 만들지 않습니다.
> 3. 필드 이름은 `DATA-MODEL.md`의 `user`와 **똑같이** 씁니다.
> 4. 이 문서는 **공유 파일**입니다. PM만 고치고, 바꿀 일이 있으면 PR 댓글로 요청합니다. 개발자1과 개발자2가 합의한 약속을 PM이 옮겨 적습니다.
> 5. 모르는 것은 `미정`으로 씁니다. 임의로 정하지 않습니다.
> 6. `>`로 시작하는 안내 문장은 지워도 됩니다.

- 상태: **초안 (Claude 작성, 개발자1·2 합의 전, PM 반영 전)** — "Google 로그인만 제공"과 "서버가 Google로 넘겼다가 돌려받는 방식(서버 리다이렉트)"은 팀원이 정했다. 경로·HTTP 상태 코드·오류 코드 이름·쿠키·환경변수 이름은 근거 문서가 없어 Claude가 채웠고 `[제안]`으로 표시했다
- 최종 수정일: 2026-11-03
- 근거: `backlog.md` US-01·US-02 (권한) 인수 조건, `first-feature.md` 2절 #4, `DATA-MODEL.md`(`user` 필드, 'LLM에 보내지 않을 정보', 시드 2번), `03-rules-states-llm.md` R8, `SETUP-PLAN.md` 3절(포트·proxy·환경변수), `API.md` 공통 규칙

## 공통 규칙
| 항목 | 내용 |
| --- | --- |
| 기본 주소 | 경로는 `/api/auth`로 시작한다 `[제안]`. 화면(5173)의 `/api` 요청은 Vite proxy가 서버 `http://127.0.0.1:8080`으로 넘긴다 (`SETUP-PLAN.md` 3절) |
| 응답 형식·오류 응답 형식 | `API.md` 공통 규칙과 같다. 오류는 `{"detail": {"code": "<오류 코드>"}}`로 코드만 주고, 사용자에게 보일 문장은 화면이 코드로 만든다 |
| 로그인 방식 | **Google 로그인만** 제공한다. 우리 서비스는 비밀번호를 받지도 저장하지도 않는다 (R8, `DATA-MODEL.md` `user`). 이메일 가입·다른 소셜 로그인은 없다 |
| 로그인 흐름 | 서버 리다이렉트(Authorization Code) 방식. 화면은 로그인 버튼에서 항목 1 주소로 이동만 하고, Google과 주고받는 일(code 교환, 사용자 정보 확인)은 **서버만** 한다. 화면은 Google 토큰을 받지 않는다 |
| 로그인 상태 유지 | 서버 세션 쿠키 하나로 유지한다 `[제안]`. 쿠키는 `HttpOnly`, `SameSite=Lax` `[제안]`. Google이 준 토큰은 **DB에 저장하지 않고 응답에도 넣지 않는다** (`DATA-MODEL.md` `user.google_sub` 설명). 쿠키 이름·만료 시간은 `미정` |
| 응답에 넣지 않는 것 | `user.id`, `user.google_sub`, Google 토큰. 화면에는 `email`, `language`만 준다 (R8 최소 수집) |
| 환경변수 (이름만) | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SESSION_SECRET_KEY` `[제안]`. 값은 `.env`에만 두고 이 문서·커밋에 쓰지 않는다. 서버에서만 읽고 `VITE_`로 시작하는 이름에 넣지 않는다 (`SETUP-PLAN.md` 3절, `CLAUDE.md`). 이름 확정은 공유 기반 담당이 `.env.example`에 반영 |
| 다른 API의 권한 규칙 | 로그인이 필요한 API(`API.md`의 `POST /api/drafts` 등)는 세션이 없으면 `401 LOGIN_REQUIRED` `[제안]`로 거절하고 작성 건을 만들지 않는다 (US-01 권한 "로그인하지 않은 사용자는 올릴 수 없다"). 남이 만든 작성 건을 보거나 확정·재분석을 요청하면 접근 거부한다 (US-01·US-02 권한). 접근 거부 코드는 `403 FORBIDDEN_DRAFT` `[제안]` (404로 숨길지는 `미정`) |
| LLM | 로그인 정보(`id`, `google_sub`, `email`)는 LLM 호출 입력에 넣지 않는다 (`DATA-MODEL.md` 'LLM에 보내지 않을 정보') |

## 항목 1: 로그인 시작 (스토리: US-01 권한)

| 항목 | 내용 |
| --- | --- |
| 요청 (경로·방식) | `GET /api/auth/google/login` `[제안]` |
| 입력 | 없음. 화면은 `fetch`가 아니라 **페이지 이동**(링크·`window.location`)으로 이 주소를 연다 |
| 출력 (성공) | `302`. Google 로그인·동의 화면으로 보낸다. 서버는 위조 방지용 `state` 값을 만들어 세션에 저장하고 Google 주소에 붙인다. 요청하는 정보 범위는 이메일과 계정 ID(`openid email`)만 `[제안]` (R8 최소 수집) |
| 실패 응답 | 서버에 `GOOGLE_CLIENT_ID` 등이 설정되지 않았으면 `500 LOGIN_NOT_CONFIGURED` `[제안]` |
| 권한 (누가 못 하나) | 없음 (누구나 시작할 수 있다) |
| 바뀌는 상태 | 없음 (작성 건 상태와 관계없음) |
| 관련 인수 조건 | `backlog.md` US-01 권한, `first-feature.md` 2절 #4 |
| 화면이 쓰는 곳 | 로그인 버튼. `DESIGN.md` 화면 목록에 로그인 화면이 없어 위치는 `미정` (업로드 화면에 들어가기 전) |

## 항목 2: 로그인 콜백 (스토리: US-01 권한)

| 항목 | 내용 |
| --- | --- |
| 요청 (경로·방식) | `GET /api/auth/google/callback` `[제안]`. Google이 사용자를 이 주소로 돌려보낸다. 화면이 직접 부르지 않는다 |
| 입력 | 쿼리 `code`, `state` (Google이 붙임). 사용자가 동의를 거절하면 `error`가 온다 |
| 출력 (성공) | `302`. 화면 첫 주소(`/`, 업로드 화면)로 보낸다 `[제안]`. 서버는 `state`가 세션 값과 같은지 확인하고, `code`를 Google 토큰으로 바꿔 `google_sub`·`email`을 확인한다. `google_sub`가 같은 `user`가 없으면 새로 만들고(`google_sub`, `email`, `language`, `created_at`), 있으면 `email`만 최신 값으로 바꾼다 `[제안]`. 그 뒤 세션에 사용자를 기록하고 쿠키를 준다. Google 토큰은 이 자리에서 쓰고 버린다 |
| 실패 응답 | 로그인 상태를 만들지 않고 `302`로 화면 첫 주소에 오류 코드를 붙여 보낸다: `/?login_error=<코드>` `[제안]`. 코드: `GOOGLE_LOGIN_CANCELED`(사용자가 거절), `GOOGLE_LOGIN_FAILED`(`state` 불일치, `code` 교환 실패, Google 응답 오류) `[제안]`. 화면은 이 코드로 안내 문장을 만든다 |
| 권한 (누가 못 하나) | 없음. 단, `state`가 없거나 다르면 위 실패 응답 |
| 바뀌는 상태 | 작성 건 상태는 바뀌지 않는다. 처음 로그인이면 `user` 행이 생긴다 |
| 관련 인수 조건 | `backlog.md` US-01 권한, `first-feature.md` 2절 #4 |
| 화면이 쓰는 곳 | 화면 첫 주소에서 `login_error`를 읽어 안내 문구 표시 (위치 `미정`) |

## 항목 3: 내 정보 (로그인 확인) (스토리: US-01·US-02 권한)

| 항목 | 내용 |
| --- | --- |
| 요청 (경로·방식) | `GET /api/auth/me` `[제안]` |
| 입력 | 없음 (세션 쿠키만. 같은 주소(proxy)라 브라우저가 자동으로 붙인다) |
| 출력 (성공) | `200`. `{"user": {"email", "language"}}`. 화면은 이 응답으로 로그인 여부를 판단하고, `language`로 표시 언어를 고른다 |
| 실패 응답 | 세션이 없거나 만료되었거나 세션의 사용자가 없으면 `401 LOGIN_REQUIRED` `[제안]`. 화면은 로그인 버튼을 보여 준다 |
| 권한 (누가 못 하나) | 비로그인 사용자 (`401`) |
| 바뀌는 상태 | 없음 |
| 관련 인수 조건 | `backlog.md` US-01 권한, US-02 권한 |
| 화면이 쓰는 곳 | 화면을 처음 열 때 (모든 화면 공통), `DESIGN.md` 업로드 |

## 항목 4: 로그아웃

| 항목 | 내용 |
| --- | --- |
| 요청 (경로·방식) | `POST /api/auth/logout` `[제안]` |
| 입력 | 없음 (세션 쿠키만) |
| 출력 (성공) | `204`. 서버 세션을 지우고 쿠키를 만료시킨다. 이미 로그아웃 상태여도 `204` `[제안]`. Google 계정 자체의 로그아웃은 하지 않는다 |
| 실패 응답 | 없음 |
| 권한 (누가 못 하나) | 없음 |
| 바뀌는 상태 | 없음 (작성 건·`user` 행은 그대로 남는다) |
| 관련 인수 조건 | 없음 (인수 조건에 로그아웃이 없다. 로그인 상태를 끝낼 방법이 필요해 넣었다 `[제안]`) |
| 화면이 쓰는 곳 | 로그아웃 버튼 (위치 `미정`) |

### 입력·출력 예시
```
로그인 시작 (화면이 페이지 이동):
GET /api/auth/google/login
→ 302 Location: https://accounts.google.com/...(client_id, redirect_uri, scope=openid email, state)

로그인 콜백 (Google이 돌려보냄):
GET /api/auth/google/callback?code=<code>&state=<state>
→ 302 Location: /            (성공, Set-Cookie: 세션 쿠키)
→ 302 Location: /?login_error=GOOGLE_LOGIN_FAILED   (실패)

내 정보:
GET /api/auth/me
응답(성공): 200
{"user": {"email": "tester@example.com", "language": "vi"}}

응답(실패): 401
{"detail": {"code": "LOGIN_REQUIRED"}}

로그아웃:
POST /api/auth/logout
→ 204 (본문 없음)

로그인 없이 업로드 (API.md 항목 1):
POST /api/drafts
응답(실패): 401
{"detail": {"code": "LOGIN_REQUIRED"}}
```
- 예시 사용자는 `DATA-MODEL.md` 시드 2번(`test-sub-0001`, `tester@example.com`, `vi`)이며 가짜 값이다.
